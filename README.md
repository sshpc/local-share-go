# local-share-go

**手机电脑局域网互传文件 · 极速版** —— 同一 Wi-Fi 下，不用数据线、不用登录、不用装 App，双击就能在电脑和手机之间传文件。

三步就能用：

1. **下载 exe**
2. **双击打开** —— 自动弹出浏览器，页面顶部就是手机扫码入口
3. **上传文件 / 下载文件** —— 手机扫码后，手机传电脑、电脑传手机都在这一个页面完成

## 功能

- **启动即自动打开浏览器**，无需记地址
- **页面顶部展示本机信息与二维码**：局域网地址、本机地址、端口、已存文件数与总大小、存储目录、运行平台；手机扫码直接打开同一页面
- **选择或拖拽文件后自动开始上传**，无需点按钮；支持多选，队列式串行上传
- 上传实时显示进度、速度与剩余时间
- **文件列表分页**：每页条数可调（5 / 10 / 20 / 50 / 100，默认 5 条），支持按文件名筛选
- **软删除 + 回收站**：删除只是移入回收站，可单个或批量删除、批量还原、彻底删除、一键清空回收站
- 下载页提供实时进度条（已下载 / 总量、速度、剩余时间），也可交给浏览器自带下载管理器
- **自动探测局域网 IP**，从 localhost 打开页面时链接与二维码自动替换成局域网地址
- **端口被占用时自动顺延**到下一个可用端口，也可配置为强制指定
- **不限文件大小**，只受磁盘空间限制
- 基于 UUID 的文件 ID，下载地址不暴露原始路径
- 下载保留原始文件名（含中文），浏览器保存下来就是上传时的名字
- 支持断点续传（`Range` 请求）
- 请求日志、panic 恢复、优雅关闭
- 配置文件 + 环境变量覆盖

## 运行

需要 Go 1.25 或更高版本。

```bash
go run .
```

或先编译再运行：

```bash
go build -o local-share-go .
./local-share-go
```

启动后访问 `http://localhost:8085`。

默认监听 `0.0.0.0:8085`，上传目录为 `./uploads`（启动时自动创建）。

仓库内的 `config.json` 把端口配置为 8081，因此直接运行时实际监听 8081。

### 交叉编译

```bash
# Windows
GOOS=windows GOARCH=amd64 go build -o upload-tool-windows-amd64.exe .

# Linux
GOOS=linux GOARCH=amd64 go build -o upload-tool-linux-amd64 .
```

## 配置

支持 `config.json` 和环境变量，环境变量优先级更高。程序从**当前工作目录**读取 `config.json`。

配置文件**允许 `//` 和 `/* */` 注释**：

```json
{
  // 监听地址，也可只写端口号如 "8081"
  "server_addr": "0.0.0.0:8081",

  // 文件存储目录
  "upload_dir": "./uploads",

  // 留空则自动探测局域网 IP
  "public_base_url": "",

  // 端口被占用时是否自动顺延
  "auto_port": true,

  // 最多向后尝试多少个端口
  "port_attempts": 20,

  // 启动后自动打开浏览器
  "open_browser": true
}
```

| 字段 | 环境变量 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `server_addr` | `SERVER_ADDR` | `0.0.0.0:8085` | 监听地址与端口，`host:port` 或仅端口号 |
| `upload_dir` | `UPLOAD_DIR` | `./uploads` | 文件存储目录 |
| `public_base_url` | `PUBLIC_BASE_URL` | 空 | 链接前缀；留空则自动探测局域网 IP |
| `auto_port` | `AUTO_PORT` | `true` | 端口被占用时是否自动顺延 |
| `port_attempts` | `PORT_ATTEMPTS` | `20` | 自动顺延的最大尝试次数 |
| `open_browser` | `OPEN_BROWSER` | `true` | 启动后是否自动打开浏览器 |

### 页面结构

从上到下三块：

- **顶部信息卡**：局域网地址、本机地址、端口、已存文件数与总大小、存储目录、运行平台，右侧是本站二维码。
- **上传区**：点击选择文件（支持多选）或把文件拖到虚线框里，**选完立即自动上传**。多文件排队串行上传，进度条逐个显示；传完页面自动刷新。
- **文件 / 回收站**：两个标签页切换。
  - **文件**：按上传时间倒序分页显示，每页条数可调（默认 5）。每行显示扩展名、文件名、大小、上传时间，可「下载」或进「进度」页；勾选后可批量删除（移入回收站）。支持按文件名实时筛选。
  - **回收站**：显示已软删除的文件及其删除时间，可勾选批量「还原」或「彻底删除」，也可以一键清空回收站。

手机扫码打开的就是这个页面，所以**手机上同样能上传和下载**。

### 删除与回收站

删除是**软删除**：只在元数据里记录删除时间，文件仍留在磁盘上，因此可以还原。

- 回收站里的文件**不可下载**（下载链接返回 404），但可随时还原。
- **彻底删除** 与 **一键清空回收站** 会真正从磁盘移除文件目录，无法恢复。
- 回收站不会被自动清理，占用空间会一直算在磁盘上。

### 自动打开浏览器

`open_browser: true`（默认）时，程序启动后自动用系统默认浏览器打开 `http://localhost:<实际端口>`。

作为后台服务运行（如开机自启、systemd）时建议关掉：

```json
{ "open_browser": false }
```

或设置环境变量 `OPEN_BROWSER=false`。没有图形界面时打开失败只会打印一行提示，不影响服务。

### 自动探测局域网 IP

`public_base_url` 留空时，程序启动时会自动探测本机在局域网中的 IPv4 地址（优先使用默认路由所在网卡，并排除 VMware、Hyper-V、Docker 等虚拟网卡）。

这样会带来两个好处：

- 控制台直接打印手机可访问的地址，例如 `局域网访问: http://192.168.1.10:8081`；
- **从 `localhost` 打开页面时，生成的下载链接和二维码会自动替换成局域网地址**，否则手机扫码拿到 `localhost` 会打不开。

用局域网 IP 访问时按请求的 Host 自然推导，不做替换。

### 端口自适应

`auto_port: true`（默认）时，如果 `server_addr` 指定的端口被占用，程序会依次尝试后续端口（如 8081 被占用则用 8082），启动日志会打印实际使用的端口。

**强制指定端口**：把 `auto_port` 设为 `false`，端口被占用时程序直接报错退出，不会换端口：

```json
{ "server_addr": "0.0.0.0:8081", "auto_port": false }
```

**强制指定链接前缀**：填写 `public_base_url` 后，程序不再做任何自动探测与替换：

```json
{ "public_base_url": "https://share.example.com" }
```

> 注意：端口自动顺延后，之前分享出去的旧链接（旧端口）会失效。如果希望链接长期稳定，请固定端口并设 `auto_port: false`。

## HTTP 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/` | 首页（上传区 + 本机信息 + 站点二维码） |
| `POST` | `/upload` | 接收 `multipart/form-data`（字段名 `file`），成功后 303 重定向到结果页 |
| `GET` | `/r/{id}` | 上传结果页（链接与二维码） |
| `GET` | `/d/{id}` | 带进度条的下载页 |
| `GET` | `/download/{id}` | 直接返回文件流（`attachment`），浏览器自带下载管理器会显示进度 |
| `GET` | `/qr/{id}` | 返回该文件的下载二维码 PNG（256×256），文件不存在返回 404 |
| `GET` | `/site-qr` | 返回指向本站（局域网地址）的二维码 PNG |
| `GET` | `/healthz` | 健康检查，返回 `ok` |
| `POST` | `/delete` | 软删除，表单字段 `id`（可重复传实现批量） |
| `POST` | `/restore` | 从回收站还原，字段 `id`（可批量） |
| `POST` | `/purge` | 彻底删除，字段 `id`（可批量） |
| `POST` | `/purge-all` | 一键清空回收站 |

首页支持这些查询参数：`?page=`（页码）、`?size=`（每页条数，限定 5/10/20/50/100）、`?view=trash`（回收站视图）。

`{id}` 必须是完整的 UUID，前缀不会命中；格式非法返回 400，文件不存在返回 404。

## 关于下载进度条

浏览器原生的文件下载不会把进度暴露给页面脚本，所以想要**页面内**的进度条，只能由脚本自己取数据：

- `/download/{id}` 是标准的文件响应（带 `Content-Length`、支持 `Range`），交给浏览器下载管理器，进度由浏览器显示；
- `/d/{id}` 是进度条页面，用 `fetch` 读取响应流，边接收边统计已下载字节、速度和剩余时间，收完后再触发保存（优先 `showSaveFilePicker`，不支持时退回 Blob 下载）。

代价是进度条方式会把文件在内存里拼装完再保存，**超大文件请用直链**交给浏览器下载管理器，避免占用过多内存。

## 存储布局

每个文件独占一个以 ID 命名的子目录，内容与元数据分开：

```
uploads/
└── 3f2b1c8a-9d4e-4a71-b0c3-5e6f7a8b9c0d/
    ├── data        # 文件内容
    └── meta.json   # 原始文件名、大小、上传时间
```

下载时按 ID 直接定位，不做目录遍历或扩展名猜测。

启动时会自动把旧版扁平布局（`uploads/<uuid><ext>`，即原始文件名丢失的版本）迁移到新布局：内容移入子目录，并按 `UUID+扩展名` 补写 `meta.json`。迁移是幂等的。旧文件因为当时没有保存原始文件名，迁移后下载名就是 `UUID.扩展名`。

文件不会自动清理，删除请手动处理 `upload_dir` 下的目录。

## 已知限制

- **无鉴权**：任何人拿到链接即可下载，文件长期保留。不要直接暴露到公网。
- **无有效期与配额**：没有过期清理，没有总容量限制，也没有单 IP 限流；磁盘写满即失败。
- **进度条页占用内存**：`/d/{id}` 在浏览器端把文件收完再保存，超大文件建议用直链。
